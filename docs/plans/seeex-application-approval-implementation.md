# 新应用申请审批实施与验收计划

2026-11-16。本文件只制定后续实施步骤。本轮没有开发业务代码、引入引擎依赖、生成/执行迁移或运行验证。

输入：[已确认需求和设计](../design/12-application-approval-workflow.md)、[组件调研](../research/approval-workflow-components.md)。场景为新应用接入申请，审批后平台办理，原申请人定向领取。

## 交付分解

| 阶段 | 后端 | 前端 | 本阶段完成条件 |
|---|---|---|---|
| A 引擎与模型边界 | 固定Flowable版本、DataSource/事务/Jackson核对；引擎适配接口和受限模型校验；迁移草案 | Arco属性控件、bpmn-js封装及只读图适配 | 依赖和许可证清楚；禁止原始引擎REST、任意脚本/Bean类；尚不创建应用 |
| B 申请与审批 | 申请/修订、编码预留、固定模板、任务资格、动作CAS、退回/撤回、历史 | 我的申请、新建/编辑、详情、待办、审批图及意见 | 申请身份不可伪造；审批通过只产生办理任务；非法状态没有按钮且后端拒绝 |
| C 办理与定向交付 | 注册原子事务、originating_request唯一、管理员快照、加密交付、站内消息、凭证CAS领取 | 办理队列/配置、结果确认、本人交付、复制与收件 | 重复办理只创建一次应用；办理人响应无明文凭证；原申请人能领取并确认 |
| D 可配置流程 | 模板草稿/版本、候选人/条件、业务绑定、发布/停用、校验/预览、会签/或签 | 设计器、属性面板、校验定位、发布差异、历史版本 | 不能绕过固定办理/交付；旧实例版本不被更新；无人审批进入兜底/异常 |
| E 通知与恢复 | Outbox租约/幂等/重试、企微消息适配、附件受控读、超时、对账、补发 | 通知中心、发送状态、异常任务、重试/补发确认 | 通知不含凭证；通知失败与业务成功分离；失效/并发领取安全可恢复 |
| F 交叉核对 | 业务/引擎事务、ACL、接口、迁移、审计和回归源码 | 页面按钮、字符串key、枚举、错误/草稿、响应式布局检查 | 静态完成与运行验收分开；不把只写源码的用例称为已通过 |

完整首期交付需要 A–F。B/C 可先作为可评审的纵向切片，但不能以固定模板就宣称“审批流配置”已完成，也不能省略 E 中的站内通知、重试和附件权限。

## 建议改动位置

- `seeex-tech-backend/web/src/main/java/com/seeex/tech/web/workflow/`：定义、实例、任务和引擎适配。
- `.../applicationrequest/`：申请、修订、预留及办理。
- `.../delivery/`、`.../notification/`：敏感交付、本人消息与Outbox；对应Mapper加入扫描范围。
- `.../registry/ApplicationRegistryService.java`：受控首次注册事务复用、申请唯一关联、绕过审批路径收敛；不复制另一套生成凭证逻辑。
- `.../governance/`：复用管理员有效性和应用边界校验，只使用批准的管理员集合。
- `.../auth/ManagementAuthorizationService.java`：新增申请/实例/任务/交付对象资格；不能只依赖全局权限码。
- `.../client/` 与 file 模块：新增受控申请附件读取上下文，保留原所有者私有文件规则。
- `seeex-tech-ui/src/features/applicationRequests/`、`features/approvals/`、`features/workflows/`、`features/notifications/`：按业务拆页面，复用现有api错误和表单组件。
- `routes/router.tsx`、`NavigationService`和资源迁移：由服务器菜单注入我的申请、待办、办理、流程管理和通知入口。
- 后续迁移版本在实施时根据仓库最新版本确定，本次不占用或假定具体V号。引擎厂商DDL与业务迁移分别核对；不启动自动建表。

## 首期资源与权限

| 页面/动作 | 拟新增权限 | 对象约束 |
|---|---|---|
| 新建申请 | app-requests:create | 有效员工本人 |
| 我的申请/详情 | app-requests:own:view | request.applicant=本人 |
| 全量申请管理 | app-requests:manage | 平台审批管理业务范围 |
| 我的待办 | workflow:tasks:view | 本人分配/候选/已办关系 |
| 审批动作 | workflow:tasks:act | 当前有效任务且排除申请人自审批 |
| 查看/编辑/发布流程 | workflow:definitions:view/write/publish | 业务作用域、模板版本与允许节点 |
| 办理 | app-fulfillments:view/act | 办理组关系和当前领取人 |
| 补发 | app-deliveries:reissue | 办理管理范围、原收件人、明确轮换确认 |
| 我的交付/通知 | app-deliveries:own:view、notifications:own:view | 仅当前本人；不能被任务查看权限替代 |
| 通知异常运维 | notifications:operate | 受控任务、理由、审计、禁止生成凭证 |
| 紧急直建 | platform:apps:override | 单独授权、原因、不能抢占活跃申请编码 |

权限码只能控制是否具备动作类别；每个端点仍验证记录归属、当前状态、任务资格、版本和有效身份。不能通过全局流程管理角色读取其他人的明文交付。

## 静态评审清单

- [ ] 每个页面按钮均有对应API、权限、状态和错误交互，详情/附件/消息与列表ACL一致。
- [ ] 每次提交固定修订和流程版本，候选人身份与角色来源可解释，自审批被后端拦截。
- [ ] ALLOW/DENY资源模型不与任务参与者混用；审批授权不会直接赋平台管理权限。
- [ ] 应用编码预留、注册唯一关联、任务CAS、交付领取CAS与通知幂等分别成立。
- [ ] 现有手工注册旁路、旧凭证轮换权限与首次交付口径明确。
- [ ] 凭证只在同事务中加密交付，不进入引擎变量、表单草稿、站内/企微消息、日志或普通附件。
- [ ] 使用独立密钥与key_id，领取过期/响应丢失/补发能够恢复且不误称可回查。
- [ ] 字典失败阻止保存；错误提示保留输入；过期任务409刷新，失败不提示成功。
- [ ] Flowable扩展属性、BPMN子集、Jackson及MyBatis事务配置与固定版本一致。
- [ ] TreeSelect key/value、Switch checked、InputNumber范围及Modeler生命周期参数正确。
- [ ] 未真实联调的企微消息明确标注，站内交付先独立闭环。
- [ ] 本轮仍为设计阶段，不勾选实现和运行验收。

## 运行验收条件

今后获准运行时，需验证同库事务回滚、引擎作业重试、并发任务决策、模板版本固定、重复办理、凭证领取、通知重放、授权附件访问及浏览器流程设计器。当前“不运行”约束仍有效，本计划不触发任何上述动作。
