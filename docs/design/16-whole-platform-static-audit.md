# 全平台功能与权限静态复查

2026-11-17。范围覆盖当前仓库认证、组织、RBAC、数据范围、应用/导航/SSO、文件、企微、审计、错误处理及新增审批链路。结论仅为源码状态，不使用清单勾选数推算完成率；本轮未运行任何项目、编译、类型检查、测试、迁移或真实API。

## 本轮发现并已修改源码的问题

| 问题 | 修复与影响 |
|---|---|
| 固定初始管理员密码 | 引导默认关闭，显式部署独立密码才创建缺失账号；不擅自修改已有生产密码 |
| JWT固定开发密钥 | 必须配置独立≥32字节AUTH_JWT_SECRET，并检查JWT头/类型/时间及长度；数据库会话与员工状态校验保留 |
| 文件固定服务令牌 | 取消开发默认值，要求≥32字节并常量时间比较，拒绝时JSON；web在未配置时明确反馈 |
| 普通员工编辑可重置登录账号 | GET/PUT账号改为employees:accounts，保留员工数据范围；对应按钮和V26权限资源一致 |
| 密码验证后重新查询身份 | 同一验证快照返回账号/员工/凭证版本，不再通过第二次手机号查询切换身份 |
| 密码重置与签发/刷新并发 | 账号auth_version CAS递增，签发记录已验证账号与版本；introspect/refresh实时核对，旧验证结果不能逃逸撤销；V27旧本地会话要求重登 |
| 生产实例内存积累刷新令牌 | 持久化模式不再把明文刷新令牌持续保存到内存测试会话表 |
| 角色停用可间接撤销DENY来源 | 角色状态变化额外要求rbac:roles:grant；前端状态字段按此只读 |
| 应用策略逐条读取和全策略扫描 | 按本人/有效角色在数据库过滤，再批量加载资源；跨应用资源核对、DENY优先保留 |
| OAuth回源持有写事务 | CAS消费状态独立提交，企微HTTP在事务外；签发由会话服务事务完成 |
| 旧应用页Tree不存在的展开参数 | 按2.66.18官方类型改为defaultExpandedKeys，新审批页一起核对 |
| 基础/RBAC表单离开丢草稿 | 统一单个路由守卫，多抽屉汇总；通用表单、角色资源、角色范围及新增审批表单报告草稿/处理中状态 |
| 首次交付与旧应用接口不一致 | 待收件应用禁止普通元数据编辑和旧轮换，补发/确认走受控事务，防止交付过时凭证 |
| 新流程并发与越权 | 请求CAS、任务状态、实时候选、申请人排除、环境绑定锁、持久编码所有权、收件人/交付版本CAS和加密AAD；接口无“任意改为通过” |
| 当前登录切换缓存 | 登录成功清理旧查询缓存；一次性凭证页面隐藏、离开、跨标签身份变化时清除；首次交付及旧凭证轮换都不把明文放入查询缓存 |
| 应用负责人存在性 | 注册/更新额外检查有效员工；owner仍不自动变为应用管理员 |

## 静态检查的证据和限制

- 179个Java源码文件做AST语法解析（包含测试源），128个record类型做构造参数数量匹配，未发现语法或构造参数数量问题；无Java编译或依赖解析。
- 全部53个TS/TSX做AST语法解析；按项目声明Arco 2.66.18官方声明文件核对组件参数名及Select继承参数，未发现语法或未知参数名；无TypeScript类型检查/lint/build。
- 对照路由/接口/权限码/请求字段/状态动作；21组前后端表单和响应类型字段名一致，12张申请相关表与DO字段对应；核对索引唯一性和固定收件人，无数据库执行或锁验证。
- 常见密钥格式扫描、候选提交文件清单、空白和成对工程规范检查；不是完整秘密检测或依赖漏洞审计。
- 回归源码未执行；实际事务回滚、幂等竞争、外部发送、Arco交互及性能结果均未知。

本轮完成的是优先申请链路的源码闭环及全模块静态复核，不宣称全部清单、全部缺陷或生产验收已完成。既有已部署默认账号需要管理员主动改密；不通过本次迁移擅自重置其密码。V25–V27和所需安全配置必须在未来发布时核对，均未在本轮执行。
