# Seeex 数据库建表 SQL 设计

本文件将 [01-database-schema.md](./01-database-schema.md) 落到 PostgreSQL 字段、约束和索引层面，作为后续 Flyway migration 的实现依据。当前仍是设计稿，表名和字段命名确认后再生成 `V2__identity_rbac.sql`。

## 1. PostgreSQL 约定

- 主键使用 `bigint generated by default as identity`；
- 时间统一使用 `timestamptz`，由数据库保存 UTC；
- 状态值使用 `varchar + check`，避免 PostgreSQL enum 迁移成本；
- 逻辑删除使用 `deleted_at is null`；
- 外键默认 `ON DELETE RESTRICT`，历史数据不级联删除；
- 审计字段的操作者可为空，表示系统任务或外部同步；
- JSON 配置使用 `jsonb`。

## 2. 通用字段

```sql
created_at timestamptz not null default current_timestamp,
created_by bigint,
updated_at timestamptz not null default current_timestamp,
updated_by bigint,
deleted_at timestamptz,
deleted_by bigint
```

`updated_at` 由应用在更新时维护；后续可增加数据库触发器作为兜底。

## 3. 基础表

```sql
create table company_profile (
    id bigint generated by default as identity primary key,
    company_code varchar(64) not null,
    company_name varchar(128) not null,
    timezone varchar(64) not null default 'Asia/Shanghai',
    logo_url varchar(512),
    wecom_enabled boolean not null default false,
    wecom_corp_id varchar(128),
    wecom_agent_id varchar(64),
    wecom_secret_ref varchar(256),
    wecom_token_ref varchar(256),
    wecom_aes_key_ref varchar(256),
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_company_profile_singleton check (id = 1)
);

create unique index ux_company_profile_code
    on company_profile (company_code) where deleted_at is null;

create table employee (
    id bigint generated by default as identity primary key,
    employee_no varchar(32) not null,
    display_name varchar(128) not null,
    internal_title varchar(128),
    internal_mobile varchar(32),
    internal_email varchar(256),
    avatar_url varchar(512),
    status varchar(32) not null default 'ACTIVE',
    source varchar(32) not null default 'LOCAL',
    primary_department_id bigint,
    job_grade_id bigint,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_employee_status check (status in ('ACTIVE','DISABLED','LEFT','LOCKED')),
    constraint ck_employee_source check (source in ('LOCAL','WE_COM','IMPORT'))
);

create unique index ux_employee_no_active
    on employee (employee_no) where deleted_at is null;

create index ix_employee_status on employee (status, deleted_at);

create table employee_account (
    id bigint generated by default as identity primary key,
    employee_id bigint not null references employee(id) on delete restrict,
    login_phone varchar(32) not null,
    phone_verified boolean not null default false,
    password_hash varchar(255),
    login_enabled boolean not null default true,
    last_login_at timestamptz,
    failed_login_count integer not null default 0,
    locked_until timestamptz,
    is_primary boolean not null default true,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_employee_account_failed_count check (failed_login_count >= 0)
);

create unique index ux_employee_account_phone_active
    on employee_account (login_phone)
    where deleted_at is null and login_enabled = true;

create unique index ux_employee_account_primary
    on employee_account (employee_id)
    where deleted_at is null and is_primary = true;

create table employee_phone_history (
    id bigint generated by default as identity primary key,
    employee_account_id bigint not null references employee_account(id) on delete restrict,
    phone varchar(32) not null,
    valid_from timestamptz not null,
    valid_to timestamptz,
    change_reason varchar(128),
    created_at timestamptz not null default current_timestamp,
    constraint ck_phone_history_range check (valid_to is null or valid_to > valid_from)
);
```

手机号应在服务层先做 E.164/国内手机号规范化，再写入 `login_phone`。

## 4. 组织和职级

```sql
create table department (
    id bigint generated by default as identity primary key,
    external_id varchar(128),
    external_parent_id varchar(128),
    parent_id bigint references department(id) on delete restrict,
    department_code varchar(64),
    name varchar(128) not null,
    sort_order integer not null default 0,
    status varchar(32) not null default 'ACTIVE',
    source varchar(32) not null default 'LOCAL',
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_department_status check (status in ('ACTIVE','DISABLED'))
);

create index ix_department_parent on department (parent_id, sort_order) where deleted_at is null;
create index ix_department_external on department (external_id) where deleted_at is null;

alter table employee
    add constraint fk_employee_primary_department
    foreign key (primary_department_id) references department(id) on delete restrict;

create table employee_department (
    id bigint generated by default as identity primary key,
    employee_id bigint not null references employee(id) on delete restrict,
    department_id bigint not null references department(id) on delete restrict,
    is_primary boolean not null default false,
    is_leader boolean not null default false,
    source varchar(32) not null,
    effective_at timestamptz,
    expires_at timestamptz,
    revoked_at timestamptz,
    revoked_by bigint,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_employee_department_range check (expires_at is null or effective_at is null or expires_at > effective_at)
);

create unique index ux_employee_primary_department
    on employee_department (employee_id)
    where is_primary = true and deleted_at is null and revoked_at is null;

create index ix_employee_department_employee on employee_department (employee_id) where deleted_at is null;
create index ix_employee_department_department on employee_department (department_id) where deleted_at is null;

create table job_grade (
    id bigint generated by default as identity primary key,
    name varchar(128) not null,
    level_value integer,
    sort_order integer not null default 0,
    external_provider varchar(32),
    external_id varchar(128),
    external_name varchar(128),
    status varchar(32) not null default 'ACTIVE',
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_job_grade_status check (status in ('ACTIVE','DISABLED'))
);

alter table employee
    add constraint fk_employee_job_grade
    foreign key (job_grade_id) references job_grade(id) on delete restrict;
```

`employee.primary_department_id` 是读取冗余字段；写入主部门时必须在同一事务同时维护 `employee_department.is_primary` 和该字段。后续可用触发器或服务层校验两者一致。

    on employee_external_identity (provider, external_id) where deleted_at is null;

    on employee_external_identity (employee_id) where deleted_at is null;

create table external_identity_conflict (
    id bigint generated by default as identity primary key,
    provider varchar(32) not null,
    external_id varchar(256) not null,
    candidate_employee_ids jsonb not null,
    reason varchar(128) not null,
    status varchar(32) not null default 'OPEN',
    resolved_employee_id bigint references employee(id) on delete restrict,
    resolved_by bigint,
    resolved_at timestamptz,

外部身份不建唯一约束是既定业务决策；同步事务必须锁定候选记录并在冲突时写入 `external_identity_conflict`。

## 6. RBAC 与数据范围

```sql
create table role (
    id bigint generated by default as identity primary key,
    code varchar(128) not null,
    name varchar(128) not null,
    description text,
    status varchar(32) not null default 'ACTIVE',
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_role_status check (status in ('ACTIVE','DISABLED'))
);

create unique index ux_role_code_active on role (code) where deleted_at is null;

create table resource (
    id bigint generated by default as identity primary key,
    parent_id bigint references resource(id) on delete restrict,
    resource_type varchar(32) not null,
    code varchar(128) not null,
    permission_code varchar(160) not null,
    name varchar(128) not null,
    path varchar(512),
    component varchar(256),
    icon varchar(128),
    sort_order integer not null default 0,
    status varchar(32) not null default 'ACTIVE',
    is_visible boolean not null default true,
    is_public boolean not null default false,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_resource_type check (resource_type in ('MENU','PAGE','TAB','BUTTON','API')),
    constraint ck_resource_status check (status in ('ACTIVE','DISABLED'))
);

create unique index ux_resource_code_active on resource (code) where deleted_at is null;
create unique index ux_resource_permission_active on resource (permission_code) where deleted_at is null;

create table menu_item (
    id bigint generated by default as identity primary key,
    parent_id bigint references menu_item(id) on delete restrict,
    resource_id bigint references resource(id) on delete restrict,
    name varchar(128) not null,
    path varchar(512),
    icon varchar(128),
    sort_order integer not null default 0,
    is_visible boolean not null default true,
    open_type varchar(32) not null default 'CURRENT_TAB',
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_menu_open_type check (open_type in ('CURRENT_TAB','NEW_TAB','EXTERNAL'))
);

create index ix_menu_parent_sort on menu_item (parent_id, sort_order) where deleted_at is null;

create table role_resource (
    id bigint generated by default as identity primary key,
    role_id bigint not null references role(id) on delete restrict,
    resource_id bigint not null references resource(id) on delete restrict,
    effect varchar(16) not null,
    effective_at timestamptz,
    expires_at timestamptz,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_role_resource_effect check (effect in ('ALLOW','DENY')),
    constraint ck_role_resource_range check (expires_at is null or effective_at is null or expires_at > effective_at)
);

create unique index ux_role_resource_active
    on role_resource (role_id, resource_id, effect)
    where deleted_at is null;

create table subject_role_assignment (
    id bigint generated by default as identity primary key,
    subject_type varchar(32) not null,
    subject_id bigint not null,
    role_id bigint not null references role(id) on delete restrict,
    assignment_source varchar(32) not null,
    source_key varchar(256),
    sync_run_id bigint,
    department_scope varchar(32),
    effective_at timestamptz,
    expires_at timestamptz,
    revoked_at timestamptz,
    revoked_by bigint,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_subject_type check (subject_type in ('EMPLOYEE','DEPARTMENT','JOB_GRADE')),
    constraint ck_assignment_source check (assignment_source in ('MANUAL','JOB_GRADE','DEPARTMENT','WE_COM','SYSTEM')),
    constraint ck_department_scope check (department_scope is null or department_scope in ('CURRENT','DESCENDANTS','CURRENT_AND_DESCENDANTS')),
    constraint ck_assignment_range check (expires_at is null or effective_at is null or expires_at > effective_at)
);

create index ix_subject_role_lookup on subject_role_assignment (subject_type, subject_id, role_id) where deleted_at is null and revoked_at is null;
create index ix_subject_role_sync on subject_role_assignment (assignment_source, source_key, sync_run_id) where deleted_at is null;

create table data_scope (
    id bigint generated by default as identity primary key,
    role_id bigint not null references role(id) on delete restrict,
    resource_id bigint references resource(id) on delete restrict,
    scope_type varchar(32) not null,
    scope_config jsonb,
    effective_at timestamptz,
    expires_at timestamptz,
    created_at timestamptz not null default current_timestamp,
    created_by bigint,
    updated_at timestamptz not null default current_timestamp,
    updated_by bigint,
    deleted_at timestamptz,
    deleted_by bigint,
    constraint ck_scope_type check (scope_type in ('SELF','DEPARTMENT','DEPARTMENT_AND_DESCENDANTS','ALL','CUSTOM')),
    constraint ck_scope_custom_config check (scope_type <> 'CUSTOM' or scope_config is not null),
    constraint ck_scope_range check (expires_at is null or effective_at is null or expires_at > effective_at)
);

create index ix_data_scope_role_resource on data_scope (role_id, resource_id) where deleted_at is null;
```

`subject_role_assignment` 是多态关联，PostgreSQL 不能用普通外键同时指向三张主体表。服务层必须校验主体存在，必要时增加触发器；禁止级联删除。

create table auth_exchange_code (

create table sync_event (

## 8. 日期序列

```sql
create table business_sequence (
    sequence_key varchar(64) not null,
    sequence_date date not null,
    next_value bigint not null default 1,
    updated_at timestamptz not null default current_timestamp,
    primary key (sequence_key, sequence_date),
    constraint ck_business_sequence_value check (next_value > 0 and next_value <= 99999999)
);
```

服务层在事务中执行 `select ... for update`，递增后生成 `yyyyMMdd + 8 位序列`。不同业务使用独立 `sequence_key`：`employee_no`、`audit_log_no`、`sync_run_no`、`sync_event_no`。数据库唯一索引作为最终兜底。

## 9. 评审结论

这份 SQL 设计已经覆盖字段、类型、约束、索引、软删除、认证会话、RBAC、数据范围、同步事件、审计和日期序列。下一步可以基于本文件生成 Flyway migration，但在生成 migration 前需要确认：

1. 手机号部分唯一索引是否只约束 `login_enabled=true`，还是所有未删除账号；
2. `subject_role_assignment` 是否接受多态主体由服务层校验；
3. `data_scope.scope_config` 的 CUSTOM JSON 是否采用部门 ID/员工 ID 两种固定数组结构；
4. 是否需要把 `employee.primary_department_id` 删除，完全以关系表为准。
